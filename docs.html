NikaScript

The scripting language built into Nikita Engine. Indentation for scope, optional type annotations, and no compile step between saving a file and seeing it run.

Install and run

Download the engine, unpack it anywhere, and run the executable. There is nothing to install and no account to create — the editor and the runtime are the same single file.

Run the executable. The project manager opens.

Press New, choose an empty folder, and pick a renderer. Forward+ suits desktop; Mobile is lighter.

Press Create & Edit. The editor opens on an empty scene.

Press F5 at any time to run the project, and F8 to stop it.

Projects are folders. Everything in them is yours: scenes are .tscn, scripts are .nika, and the project file is project.nikita.

Your first script

A script is attached to a node and gives that node behaviour. Add a Node2D to the scene, right-click it in the scene tree, and choose Attach Script.

from Node2D

fn _ready():
	print("Hello from NikaScript")

Press F5. The message appears in the Output panel at the bottom of the editor.

Two things are worth naming straight away. from says which type the script builds on, so the script is a Node2D and can use everything one can do. _ready is called once, automatically, when the node enters the scene — you never call it yourself.

Variables and constants

let declares a variable. The type can be left to the engine, inferred once and then enforced, or written out.

let health = 100              # no fixed type, can hold anything later
let speed := 240.0            # type inferred as float, and kept
let title: String = "Level 1"  # written out

const MAX_LIVES = 3            # cannot change, known at compile time

Prefer := in real code. A typed variable catches mistakes as you type, makes autocompletion sharper, and runs faster than an untyped one.

Built-in types

TypeHolds
int, floatWhole and fractional numbers
booltrue or false

ArrayAn ordered list: [1, 2, 3]
DictionaryKeys to values: {"hp": 10}
Vector2, Vector3Positions and directions

Every class in the engine — Node2D, Timer, Texture2D and the rest — is also a type you can write after a colon.

Functions

fn declares a function. Parameter types and a return type are optional, and both are worth writing.

fn damage(amount: int) -> void:
	health -= amount

fn distance_to_origin(p: Vector2) -> float:
	return p.length()

fn greet(who := "player"):     # default value, type inferred
	print("hello, ", who)

A function that returns nothing is written -> void. A function with no body yet needs pass, which does exactly nothing and exists so the indentation has something to hold.

Control flow

Blocks are marked by indentation and opened with a colon. Use tabs or spaces consistently — the engine will tell you if you mix them.

if health <= 0:
	die()
elif health < 20:
	play_heartbeat()
else:
	pass

for i in range(3):        # 0, 1, 2
	print(i)

for item in inventory:   # any array or dictionary
	print(item)

while not is_finished():
	step()

match

match compares a value against patterns and runs the first that fits. _ catches everything else.

match state:
	"idle":
		play("idle")
	"run", "sprint":      # several patterns at once
		play("run")
	_:
		play("idle")

Scripts and nodes

A scene is a tree of nodes, and a script gives one node its behaviour. These are the pieces you will use in nearly every script.

from CharacterBody2D

@export let speed: float = 240.0
@onready let sprite: Sprite2D = $Sprite2D

fn _ready():
	sprite.modulate = Color.CYAN

fn _process(delta: float) -> void:
	rotation += delta
PieceWhat it does
@exportShows the variable in the Inspector, so it can be set per node without touching code
@onreadyWaits until the node is in the tree before running the value — needed for $ lookups
$NameFinds a child node by name; $Path/To/Node goes deeper
%NameFinds a node marked as a scene-unique name, wherever it sits
_readyRuns once, when the node enters the tree
_processRuns every frame; delta is the seconds since the last one
_physics_processRuns at a fixed rate — use it for movement and physics
selfThe node this script is on
Always multiply movement by delta. Frames do not arrive at an even pace, so a speed written per-frame runs faster on a faster machine. Multiplying by delta makes it a speed per second instead.

Signals

A signal is an announcement a node makes without knowing or caring who is listening. It is how one part of a game tells another that something happened, without the two being wired together.

from Node2D

signal died
signal damaged(amount: int)

let health := 100

fn hit(amount: int) -> void:
	health -= amount
	damaged.emit(amount)
	if health <= 0:
		died.emit()

Somewhere else, a node listens:

fn _ready():
	$Enemy.died.connect(_on_enemy_died)

fn _on_enemy_died() -> void:
	score += 10

Note that _on_enemy_died is passed without brackets. Brackets would call it immediately; without them you are handing over the function itself.

Waiting

await pauses a function until a signal fires, without freezing the game.

fn flash() -> void:
	modulate = Color.RED
	await get_tree().create_timer(0.2).timeout
	modulate = Color.WHITE

Classes and enums

Every script is already a class. class_name gives it a global name, so it appears in the node creation dialog and can be used as a type anywhere.

class_name Weapon
from Node2D

enum Kind { MELEE, RANGED }

@export let kind: Kind = Kind.MELEE
@export let damage := 10

static fn sword() -> Weapon:
	let w := Weapon.new()
	w.damage = 25
	return w

A script can build on another script, not only on an engine class, and super calls the version it inherited.

from Weapon

fn _ready():
	super()          # run Weapon's _ready first
	damage = 50

Smaller classes can live inside a script with class, which is handy for plain data that never becomes a node.

class Slot:
	let item := ""
	let count := 1

Loading resources

There are two ways to bring in a scene, texture or sound, and the difference is when it happens.

const Bullet = embed("res://bullet.tscn")   # loaded with the script

fn _ready():
	let icon = load("res://icon.png")      # loaded when this line runs

embed resolves while the script is being compiled: the file must exist, and it is in memory before your first line runs. load happens later, when execution reaches it, which suits things you may never need.

To put a scene into the world, make an instance of it and add it as a child:

fn shoot() -> void:
	let b := Bullet.instantiate()
	b.global_position = global_position
	get_parent().add_child(b)

Tutorial 1 · Move a character

A character you can walk around with the arrow keys or WASD, in about ten lines.

Add a CharacterBody2D to your scene.

Give it two children: a Sprite2D with any texture, and a CollisionShape2D with a circle shape.

Attach a script to the CharacterBody2D and replace it with the code below.

from CharacterBody2D

@export let speed: float = 240.0

fn _physics_process(delta: float) -> void:
	let direction := Input.get_vector("ui_left", "ui_right", "ui_up", "ui_down")
	velocity = direction * speed
	move_and_slide()

Press F5 and walk around. get_vector hands back a direction of length 1 in whichever way the keys are pressed, so diagonal movement is not faster than straight — a bug worth avoiding for free.

The ui_* actions exist in every new project. To use your own names, open Project → Project Settings → Input Map and add them there; speed is exported, so you can also tune it per node in the Inspector without editing the script.

Tutorial 2 · Pickups and score

Coins that vanish when touched, and a score that counts them. This is signals doing real work: the coin does not know the score exists.

Make a new scene with an Area2D at its root, plus a Sprite2D and a CollisionShape2D. Save it as coin.tscn.

Attach this script to the Area2D.

from Area2D

signal collected

fn _ready():
	add_to_group("coins")
	body_entered.connect(_on_body_entered)

fn _on_body_entered(body: Node2D) -> void:
	if body.is_in_group("player"):
		collected.emit()
		queue_free()

In your main scene, drop a few coin.tscn instances around, and add a Label under a CanvasLayer named ScoreLabel.

Select your player node and add it to the group player in the Node → Groups panel.

Attach this script to the root of the main scene.

from Node2D

let score := 0

@onready let label: Label = $CanvasLayer/ScoreLabel

fn _ready():
	for coin in get_tree().get_nodes_in_group("coins"):
		coin.collected.connect(_on_coin_collected)
	_refresh()

fn _on_coin_collected() -> void:
	score += 1
	_refresh()

fn _refresh() -> void:
	label.text = "Score: %d" % score

Groups are why this stays tidy. The main scene never names a single coin, and a coin never names the score — add fifty more coins in the editor and nothing in the code changes.

queue_free, not free. The coin is in the middle of reporting a collision when it decides to disappear. queue_free waits for the end of the frame, so nothing is deleted while the engine is still using it.

Tutorial 3 · Spawning and timers

Enemies that appear on a schedule, at a random spot, and clean up after themselves.

Build an enemy scene and save it as enemy.tscn.

Attach this to the root of the main scene.

from Node2D

const Enemy = embed("res://enemy.tscn")

@export let every_seconds: float = 1.5
@export let area := Vector2(900, 500)

fn _ready():
	while true:
		await get_tree().create_timer(every_seconds).timeout
		_spawn()

fn _spawn() -> void:
	let e := Enemy.instantiate()
	e.position = Vector2(randf() * area.x, randf() * area.y)
	add_child(e)

The loop looks like it should freeze the game, and it would in most languages. await is what saves it: the function steps aside until the timer reports back, and everything else keeps running in the meantime.

Give the enemy a life of its own, and a limit:

from Node2D

@export let speed := 120.0
@export let lifetime := 6.0

fn _ready():
	await get_tree().create_timer(lifetime).timeout
	queue_free()

fn _process(delta: float) -> void:
	position.y += speed * delta
Always give spawned nodes an ending. Anything that spawns forever and never frees will fill memory until the game stops. A lifetime, a screen boundary, or a cap on the number alive — any one of them is enough.
